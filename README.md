# 循塑 Xunsu

种下一颗好奇，收获一份心意。通过互动种植、环保锦囊与编织，帮助消费者了解农产品，再自主决定是否购买实物。

这是可离线体验的本地网站，使用原生 HTML、CSS、JavaScript 和程序化 SVG 场景，无第三方运行依赖。

## 打开网站

直接双击 `index.html`，即可体验所有前端流程。推荐使用近期版本的 Chrome、Edge、Safari 或 Firefox。

也可以在目录中运行：

```sh
npm start
```

访问 <http://127.0.0.1:4173>。支持 `PORT=其他端口 npm start`。

## 一次完整体验

1. 点击“选择身份，开始这一季”，从5个身份中选择一个；可自愿开启仅本机保存。
2. 选择文玩玉米。过了示范播种期时，明确进入“春播体验”，不会改动真实日期。
3. 完成浇水、叶片观察、土壤照料；每项每季领取一次积分。三项完成即可成熟，避免积分耗尽后卡住。
4. 阅读环保锦囊；首次正确回答各得20积分。可自愿用20积分增加15成长值。
5. 进入编织工坊，按提示交替从左、从右穿入，共8纬。首轮免费，后续每轮10积分；首奖只领取一次。
6. 收获、选择包装。普通编织款需完成编织，并有30积分，体验订单生成时才扣积分。
7. 查看卖家、产地、生长图与心愿的待核实位置，确认必要游戏摘要用途，生成**体验订单**。
8. 在“体验订单”查看状态，也可导出手记、开启下一季或删除本机记录。

**体验订单不扣款、不安排实物发货。** 页面明确标注示例价，未接入真实卖家、库存、运费、支付和物流，不冒充已开展真实销售。

## 项目资料与真实性

- 已提供的背景：文玩玉米农户—手工业者—消费者，减塑包装、共创和经济可行性。
- 手工业者、生态商店、青年消费者的需求，来自用户先前提供的调研记录归纳。不是逐字访谈，也不代表这些对象已签约供货。
- 发起者和7位守村人的姓名、照片、第一人称心愿、真实产地及批次生长图片尚未提供，全部保留为待授权位置，没有编造真人资料。
- 场景、作物阶段和产品图均为 SVG 示意，不标称真实农场照片。
- 默认季候是**华北月份示例**，以 `Asia/Shanghai` 读取真实日期和昼夜；真实种植地核实后需要校准播种窗口。季节体验不代表真实农时。
- 39元商品价、8元包装加价是界面演示值，不是报价。无真实运费数据，未擅自按全国统一运费结算。
- 填充物是可用候选范围内的稳定搭配建议，重复进入不会反复抽取经济权益。实际材料、清洁干燥处理、保护效果、成本和运输条件需要确认。
- 非遗联名只展示合作筹备状态，没有使用传承人名义或宣称已上架。

## 上线前替换内容

编辑 `data.js`，录入并核实：

- `farm`：真实地点、时区、季候与播种窗口。
- `cases`：本人授权的姓名、心愿与带日期、批次的真实图片。
- `commerce`：卖家资质、SKU规格、实际价格、库存、发货地、运费规则与服务端结算入口。
- `crops`：其他农产品的播种窗、生长阶段、商品规格及是否开放实物。

当前 `commerce.mode` 固定走演示流程。**不要只把它改成 `live` 就声称能收款。** 真实交易需要另行实现服务端订单、库存校验、支付创建与签名验证、支付回调去重、退款与物流查询，以及收货信息授权和保护。前端不得保存支付密钥。此版本在缺少真实接入时明确阻止真实交易，不会假造支付成功或物流状态。

## 隐私与人力

默认临时体验，勾选后才写入本机 `localStorage`。不上传游戏数据、无埋点，不保存体验称呼与地区。导出仅含必要游戏摘要。真实收货信息尚不收集。

角色切换与场景由前端完成；任务奖励去重、包装候选搭配和编织反馈自动处理，减少人工陪玩。卖家内容与实物确认仍需真实运营。

## 检查和打包

需要 Node.js 18或以上：

```sh
npm test
npm run build
```

构建输出 `dist/`，可部署到任意静态服务器或 GitHub Pages。前端文件均使用相对路径，适配仓库子路径。

## GitHub 公开协作

授权登录后，在本目录运行：

```sh
gh auth login
bash scripts/publish-github.sh
```

脚本创建名为 **Xunsu** 的公开仓库并推送本地代码。若已存在远程或同名库，会停止，避免覆盖。公开后所有人可以查看、Fork、修改自己的副本并提交 Pull Request。GitHub 不提供让任意匿名访客直接写入你主仓库的设置；需要直接写入的成员，应通过仓库 Settings → Collaborators 邀请。

已提供 MIT 代码许可证、贡献说明和可手动触发的 Pages 工作流模板（`scripts/github-pages.yml.example`）。需要发布时，将模板复制到 `.github/workflows/pages.yml`，并在 Pages 设置中选择 GitHub Actions。工作流写入需要相应 GitHub 权限；本地交付和代码入库均不会自动发布网站。

## 文件

- `index.html`、`styles.css`、`app.js`：界面、交互与移动端适配。
- `scene.js`：响应季节、日夜、作物阶段的程序化 SVG 场景。
- `data.js`：内容与运营配置。
- `core.js`：积分、成长、购买资格与包装规则。
- `tests/core.test.cjs`：有意义的核心状态与积分测试。
- `server.cjs`：只暴露网站静态文件的本机预览服务。
